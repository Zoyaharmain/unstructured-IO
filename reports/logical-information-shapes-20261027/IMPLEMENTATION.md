# Logical information shapes

The requested model is: source fragments → proposed logical entity → existing schema fields → evidence-validated record.

A section is a container. A logical record is one entity inside that container. Summary, contact and skills use complete section context. Experience keeps one record per job; projects keep one record per project. Multiple jobs are not compressed into one job, and wrapped fragments are not presented as independent entities.

## Implementation

`local_api/services/logical_blocks.py` adds a derived `semantic_frame` to every logical block:

- `schema_target`: existing schema category, or null when record ownership is unresolved.
- `meaning`: section label describing the proposed kind of information.
- `scope`: complete_section, one_record, or unassigned_fragments.
- `field_slots`: allowed names and multiplicities from the existing SUBSCHEMAS registry, with original source IDs as provisional field hints.
- `interpretation_status`: proposed or requires_association.

Field hints are restricted to the owning logical block. Unknown fields and references outside that block cannot enter the hints. No field value, narrative meaning, certainty score or evidence is generated by this layer. Empty hints do not mean the information is absent. Frames are recomputed after ownership changes rather than cached with stale source references.

`local_api/services/llm_schema_mapping.py` passes these frames through the existing logical_blocks payload. Instructions require the mapper to establish the entity, assemble its context, verify source hints, then extract into the allowed field shape. Existing source, record-ownership and subschema validators still control acceptance. This adds no provider call or new paid pipeline stage.

`local_api/static/sections.js` shows the proposed meaning and scope above each block's full text. Original source inspection remains available. Fields and detailed schema results still come from the validated mapper.

## Limits

A semantic frame makes a proposed grouping explicit; it does not prove that grouping correct. Existing local boundary proposals and optional LLM review continue to determine ownership. Overlapping or unowned fragments remain explicit rather than being forced into a convenient shape. This change does not introduce a trained universal semantic classifier or guarantee every resume layout.

## Validation

Focused offline tests: 45 passed. New tests cover registry-derived shapes, record-local source hints, exclusion of unknown fields, ownership changes and complete summary context. JavaScript syntax and diff whitespace checks passed. No paid calls.

Full offline regression suite: **623 passed in 136.27 seconds**. Live provider behavior was not exercised.
