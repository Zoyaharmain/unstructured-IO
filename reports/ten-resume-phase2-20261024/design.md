# Phase 2: source-preserving section review and audit chunks

The implementation is in `local_api/services/review_chunking.py`. This phase is offline: no live provider calls, extraction/detection/embedding runs for the ten-resume replay, 350-resume rerun, education normalization or candidate-search implementation. Phase 1's classifier and fingerprint behavior are preserved.

## Identity, ownership and evidence

The planner binds the full typed extracted inventory with SHA-256 and optionally an original-byte document SHA-256. The CLI supplies the original-byte SHA; the element-only section API cannot know PDF bytes, so its binding explicitly says the original document hash is unavailable instead of inventing it. Offline replay supplies the original frozen PDF digest. Inventory hashes include the saved metadata and text.

Chunks use immutable global `e<element>:<start>:<end>` source IDs. Source targets carry original offsets, page, lane, PDF-line layout, current parent, allowed source-safe split offsets and established record key. Each owned target occurs once. Established employer/title/date or qualification/institution blocks are read-only context. No records are generated by the provider. Context can overlap chunks, but context-only IDs cannot be assigned. Grouping prefers complete supplied records; oversized groups split into source units while retaining the same anchors. Original inventory order is retained in the merged result, including when record groups interleave across columns.

A single oversized source target can split only at its existing allowed offsets. Such transport-only pieces coalesce back when their returned categories agree, preventing artificial block/record boundaries. If even a safe unit or required context cannot fit, the plan marks it unreviewable; the stage performs no partial commit and never calls that outcome complete. It does not truncate strings, omit owned source, invent a continuation, or force a category.

The existing whole-document `uN` response contract is retained for requests already within all guards. It still supplies global source IDs and exact source offsets in its payload. Only the chunk protocol uses global source IDs directly as response targets. Whole-document saved responses must not be replayed as chunk-local responses.

## Serialized budgets and request limits

The guard measures the actual serialized JSON request body, including model, roles, messages, escaped evidence, read-only context, advisory feedback, response format, thinking mode and max_tokens. It reserves an output allowance and constrains owned-target count and the conservative input policy bound. It does not simply compare resume text lengths or increase the prior character limit.

New optional settings, without modifying .env:

| Setting | Default | Scope |
|---|---:|---|
| DEEPSEEK_REVIEW_MAX_INPUT_TOKENS | 100000 | Conservative serialized input-policy bound |
| DEEPSEEK_REVIEW_CONTEXT_TOKENS | 128000 | Configured local input + reserved output guard |
| DEEPSEEK_REVIEW_DOCUMENT_REQUESTS | 32 | Requests for the same inventory within an injected budget |
| DEEPSEEK_REVIEW_PASS_REQUESTS | 16 | Placement + audit requests within a pass |
| DEEPSEEK_REVIEW_TOTAL_REQUESTS | 128 | Requests across a shared run budget |

Existing max_input_chars, max_units and max_tokens remain enforced. The token policy uses serialized UTF-8 bytes as a deliberately conservative bound for byte-tokenized inputs, **not exact DeepSeek token accounting or verification of the model's actual context window**. The configured context value is a local policy, not a newly verified provider specification. Real truncation/finish reasons still fail closed through the existing transport. The output guard ensures room for ordinary complete target acknowledgements; it cannot guarantee that every possible verbose finding will fit. Tokenizer calibration remains a paid-pilot limitation.

`RequestBudget` tracks per-pass, per-inventory/document and global attempts, including failed attempts. It supports one shared budget across a batch; the CLI shares one across its placement/audit/feedback stages, and offline replay shares one across all ten documents. Independent API requests are separate request scopes, not a server-lifetime global allowance. Any future batch driver must explicitly inject one shared budget and enforce its approved document scope; old batch scripts were not rerun or silently upgraded. This is not an authorization ledger. The earlier 40-call approval is not reused.

There are no automatic per-chunk retries. Existing bounded feedback/invalid-placement limits govern subsequent attempts; all attempts also consume the request budget. Budget exhaustion returns incomplete coverage and retained validated output.

## Validation and aggregate behavior

A section response may contain only owned target IDs. Existing strict assignment validation checks all target coverage, offsets, permitted cuts, categories, gaps, duplicates, overlaps and conflicting decisions. The merged union is validated again against the original spans before any new placement is committed. Any failed chunk retains the entire preceding valid section result. Aggregate coverage is incomplete on failure; valid previous content is not relabeled as successfully re-reviewed.

Confirm-only responses preserve existing entries and their source membership exactly. Where a real category change requires the existing global section-building path, an explicit source-overlap ownership crosswalk reports old/new parents, record IDs and source IDs. It is not semantic truth or automatic ground-truth realignment. Existing grouping remains provisional; chunking cannot guarantee a provider's semantic association decisions.

## Compact schema audits

The audit adapter uses canonical units rather than duplicating the entire response, field index and metadata:

- Each populated nested field/list item with its exact evidence and record key.
- Each unresolved predefined child field.
- Every residual source reference.
- Every original raw source span as an omission-check target, including unmapped/unknown content.
- Required legacy-field candidates and compact legacy scalar values, with recorded source references where available.
- Adjacent established-record association/boundary targets with exact source-backed anchors.

Units preserve parent, record, list index and source IDs. Records pack together when possible; oversized record groups split at units. Single field items that cannot fit with required context are explicitly unreviewable, not truncated or silently omitted. Audit anchors lacking recognized header fields fall back to the first/last source blocks of that established record, not arbitrary neighboring elements. Ambiguous supplied ownership stays provisional.

Every chunk must acknowledge every owned audit unit exactly once. Findings must target a unit in that chunk and cite one of that unit's own source IDs or its **same-record** context (boundary units explicitly own both record contexts). A quote from another record in the same request is not automatically acceptable. Incomplete acknowledgements, duplicate IDs, foreign sources, malformed findings, transport errors and exhausted budgets cannot produce a complete clean audit. Partial findings remain separate, with status incomplete. Audits are advisory and never rewrite schema values; previous pass artifacts remain preserved.

Coverage completion means that the response acknowledged the configured targets, not that the provider found every semantic error. Adjacent boundary checks are not exhaustive nonadjacent entity resolution. There is no cross-candidate search, no new human labels and no semantic-accuracy claim.

## Integration

`llm_section_review.py` chooses guarded whole-document or chunked placement, preserving all-or-nothing source validation. `single_resume_pipeline.py` carries feedback into planning before serialization and shares the budget across stages; it retains Phase 1's semantic fingerprint and existing bounded-loop behavior. `check_single_resume.py` invokes the compact audit helper with the same document hash and budget. The source schema, mapper, abbreviated education-year policy, extraction and embedding code were not changed.
